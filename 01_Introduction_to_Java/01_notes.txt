# Introduction to Java

## Background (1980s–1990s)
During the 1980s and 1990s, C and C++ were widely used programming languages because they were:
- Fast
- Efficient
- Low-level
- Close to hardware
- Capable of directly interacting with the processor
They were ideal for system-level programming and performance-critical applications.
However, they had limitations, especially regarding portability and security.


## Why Was Java Introduced?

### Problem: Portability in C/C++
C and C++ programs are platform dependent.
- Machine code generated on one platform (combination of processor + operating system) will not run on another platform.
- To run the same program on a different system, the source code must be recompiled using that platform’s specific compiler.

### Why Different Machine Code Is Generated on Different Platforms
- Operating System Differences
    - Each operating system has its own system libraries.
    - Programs call OS-specific libraries to execute instructions.
    - Since libraries differ, the generated machine code also differs.
- Processor Differences
    - Different processors have different architectures.
    - Each processor follows its own Instruction Set Architecture (ISA).
    - Therefore, machine instructions vary from processor to processor.
Because of these differences, C and C++ programs are platform dependent.


## Problems with C/C++
- Platform dependency
- Complexity (not beginner-friendly)
- Manual memory management
- Pointer-related vulnerabilities
- Security vulnerabilities (manual memory management, pointers, etc.)

## Solution Provided by Java
Java was designed to overcome these issues by being:
- Portable
- Simple
- Secure


## Bytecode Concept
Java introduced a new execution model:
Java Source Code (.java)
        ↓
Compiled by javac
        ↓
Bytecode (.class)
        ↓
Executed by JVM

### How It Works
- The .java source file is compiled by the javac compiler.
- The compiler generates bytecode (.class file).
- The bytecode is executed by the JVM (Java Virtual Machine).
- The JVM converts bytecode into machine code suitable for the underlying platform.


## JVM (Java Virtual Machine)
The JVM is a virtual machine that:
- Executes Java bytecode
- Manages memory
- Performs garbage collection
- Provides security
- Enables platform independence
Since the .class file runs on any system that has a JVM, Java achieves portability.


## Platform Independence
Java follows the principle:
WORA – Write Once, Run Anywhere
A Java program can run on any platform without recompilation, as long as a compatible JVM is available.


## Simplicity of Java
C and C++ include several complex features such as:
- Pointers
- Multiple inheritance (especially in C++)
- Manual memory allocation and deallocation (malloc, free, new, delete)
These features increase complexity and can lead to issues like memory leaks and segmentation faults.

Java improves simplicity by:
- Removing explicit pointer manipulation
- Not supporting multiple inheritance through classes (uses interfaces instead)
- Providing automatic memory management through Garbage Collection
- Offering a cleaner and more consistent syntax
As a result, Java is easier to learn, write, and maintain compared to C and C++.


## Security of Java

### Java in Backend Development
Java has been widely used for backend development.

A Servlet is a Java class that:
- Runs on a web server
- Handles client requests (such as HTTP requests)
- Processes data
- Sends responses back to the client

Request–Response Flow:
Browser → HTTP Request → Web Server (e.g., Tomcat) → Servlet → Response → Browser

Servlets run inside a controlled server environment, making them secure and reliable for enterprise applications.


### Java in Frontend (Applets)
Java was also used on the client side through Applets.
- Applets were lightweight Java programs
- Transmitted over the internet
- Executed inside the user's web browser
However, applets are now obsolete due to security concerns and modern web technologies.

### JVM Security Model
The JVM (Java Virtual Machine) provides a secure runtime environment.

It ensures security by:
- Running bytecode inside a controlled environment
- Verifying bytecode before execution
- Restricting unauthorized access to system resources
- Using a sandbox model to prevent harmful operations
The sandbox model ensures that untrusted code cannot perform dangerous actions such as accessing local files or executing system-level commands without permission.


## Can C/C++ Be Platform Independent?
C and C++ are inherently platform dependent because they compile directly into machine code specific to a processor and operating system.
However, platform independence can be achieved by introducing an intermediate runtime environment.


### Example: C#
Microsoft developed C#, which:
- Compiles into Intermediate Language (IL)
- Runs on the .NET runtime (CLR – Common Language Runtime)
- Achieves platform independence similar to Java (especially with .NET Core/.NET 5+)


### Python and Platform Dependence
Python is generally considered platform independent because:
- Python code is compiled into bytecode (.pyc)
- The bytecode runs on the Python Virtual Machine (PVM)

However, like Java, Python requires its runtime environment to be installed on the target system.
